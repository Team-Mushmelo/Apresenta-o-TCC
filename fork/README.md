# O que são forks?

![Ilustração de forks](/img/forks.png)

</div>

## O que é um Fork no GitHub?

Em termos simples, um fork no GitHub é uma cópia de um repositório de código que é feita por um usuário para seu próprio espaço de trabalho. Quando você faz um fork de um repositório, você cria uma versão pessoal desse projeto em sua própria conta do GitHub. Essa cópia é completamente separada do repositório original, permitindo que você faça alterações sem afetar o projeto principal.

## Por que fazer um Fork?

Fazer um fork é útil por várias razões:

1. **Contribuição a Projetos Open Source**: Muitos projetos de código aberto incentivam os contribuidores a fazerem forks do repositório principal para propor melhorias ou corrigir problemas. Ao fazer um fork, você pode trabalhar em suas alterações isoladamente antes de enviar uma solicitação para que suas mudanças sejam incorporadas ao projeto original.

2. **Experimentação Segura**: Fazer um fork permite que você experimente livremente com um projeto sem medo de quebrar o código principal. Você pode fazer alterações no seu fork e testar novas ideias sem impactar diretamente o projeto original.

3. **Acesso aos Códigos Fonte**: Com um fork, você pode acessar todo o código fonte do projeto. Isso é útil para aprendizado e para entender como os projetos funcionam.

## Como fazer um Fork?

Fazer um fork no GitHub é fácil:

1. **Visite o Repositório**: Vá para o repositório que deseja forkar no GitHub.

2. **Clique no Botão Fork**: No canto superior direito da página do repositório, você verá um botão chamado "Fork". Clique nele.

3. **Escolha o Destino**: Escolha onde deseja fazer o fork: geralmente será para a sua própria conta do GitHub.

4. **Aguarde o Processo**: O GitHub vai criar uma cópia do repositório na sua conta. Isso pode levar alguns segundos.

5. **Trabalhe no Seu Fork**: Depois que o fork for concluído, você terá seu próprio repositório com uma cópia exata do projeto original. Agora você pode clonar o seu fork para o seu computador, fazer alterações, criar novos branches e enviar suas contribuições de volta para o projeto original por meio de pull requests.
